1. `max_epoch` is number of times we loop and train, the more you increase, the better model gets
2. `step_per_epoch` is number of steps we allow to run whether episode is over or not, some episodes can be 10 steps or 500 steps
3. `step_per_collect` we keep collecting data into our replay buffer until X number then we train on it, if steps per epoch is 200 but step per collect is 50 we train 4 times, also increase buffer size/steps per collect size makes training better as we have more experience and it averages out, but it increasing time taken to train
4. `repeat_per_collect` we said if steps per epoch is 200 but step per collect is 50 we train 4 times, if repeat_per_collect = 1, we only train 4 times, but if its 2 we train 8 times in total, if we set number to 20, that is too much will lead to overfitting because we are training on same data 20 times to put it into prespective a single 1, means we use all data in each buffer to train once, 2 means we do that on same data twice, 20 ... too much However there is a catch in old algorithms you want to repeat per collect once to avoid overfitting, but PPO has mechanism to prevent this even if repeat_per_collect is more than 2, that is , network is not allowed to make drastic changes during training , this makes
PPO data efficient in a sense you don't need to collect many data, you can reuse data again many times 4 to 10 times accordin  to gemini to train

5. `batch_size` is size of data we feed into network, if its 32 batch_size,  and if steps per epoch is 200 but step per collect is 50 we train 4 times, if we have to focus on a single training, we have 50 experiences in buffer, we have batch_size 32 but we still train using all 50 experience but How? we split it, initally we feed 32 into network to update its weights then 16, btw batch_size is max size not restrictly 32

6. `batch_size BIG VS SMALL` if batch_size is BIG it is better we get more smooth out performance graph why? because we are looking at all data at once and average moving direction of weights so it is more smooth, also GPU prefers to feed big batch_size why? because it is repeating instructions that can be parallised in one go, HOWEVER it is good for machine learning but for RL ironically we need some noisy that we can get from small batch_size , we will get jittery performance graph because some batchs experience are different, we dont see big picture so we know where to go, but jittry/laggy, ironically that is good for RL because RL is all about randomness we wnat agent to take some randomness in decision to avoid stuck in local optima, like agent not moving to avoid dying aka you are getting reward but that is local optima, so we can use big batch still in RL but if we notice agent not improving we switch to small batch size
